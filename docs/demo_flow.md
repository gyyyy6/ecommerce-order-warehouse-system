# 演示流程（demo_flow）

> 阶段：P5 页面  
> 状态：已实现（待用户实测）  
> 目标：用 5~10 分钟演示订单列表、创建订单、库存不足回滚、订单详情 join、状态修改、取消回补库存、删除明细。

```bash
# Linux VM
cd /path/to/DataBase
source .venv/bin/activate

python3 scripts/init_db.py count
```

- `TOTAL > 100000`（实测值回填）；

- Windows 浏览器能打开 `http://<VM_IP>:5000/health`。

## 2. 演示步骤

### 2.1 打开订单列表页

Windows 浏览器访问：

```text
http://<VM_IP>:5000/orders
```

演示点：

- 列表来自 `/api/orders`；
- 显示客户、状态、时间、金额、明细行数/件数、物流；
- 分页与筛选。

### 2.2 筛选订单

操作：

1. 客户 ID 输入 `1`；
2. 状态选择 `PAID`；
3. 选择日期范围；
4. 点击“筛选”。

预期：

- 列表只显示符合条件的数据；
- 分页信息更新；
- 空结果时显示“没有符合条件的订单”。

### 2.3 创建订单（正常路径）

操作：

1. 客户 ID 输入 `1`；
2. 收货地址可留空（使用客户默认地址）；
3. 商品搜索输入“蓝牙”；
4. 选择一个库存充足的商品；
5. 数量输入 `2`；
6. 点击“添加明细”；
7. 再添加另一件商品；
8. 点击“创建订单”。

预期：

- 返回订单号；
- 订单状态 `PENDING`；
- 订单明细行数与商品数一致；
- 商品库存减少；
- 自动生成一张物流单（状态 `CREATED`）；
- 列表中出现新订单。

### 2.4 创建订单（库存不足回滚）

操作：

1. 新建订单；
2. 选择一个低库存商品（种子数据前 30 个商品库存较低）；
3. 数量输入超过库存的值；
4. 点击“创建订单”。

预期：

- 页面提示“库存不足”；
- 数据库中没有该订单头；
- 没有订单明细；
- 没有物流单；
- 其他商品库存没有被扣减（整单回滚）。

证据：

- 页面错误截图；
- 创建前后 `SELECT COUNT(*) FROM orders`；
- 创建前后商品库存查询。

### 2.5 查看订单详情（多表 join）

操作：

1. 在列表点击订单号；
2. 或直接访问 `http://<VM_IP>:5000/orders/<order_id>`。

演示点：

- 客户姓名、邮箱、电话；
- 订单状态、下单时间、收货地址；
- 明细中的商品、SKU、分类、数量、单价、行金额；
- 物流承运商、运单号、物流状态、发货时间；
- 总金额、总件数、明细行数。

预期：数据与数据库 join 查询一致。

### 2.6 修改订单状态

操作：

1. 在列表中找到 `PENDING` 订单；
2. 状态下拉选择 `PAID`；
3. 点击“更新”。

预期：

- 状态变为 `PAID`；
- 列表刷新；
- 不允许从 `PENDING` 直接改为 `SHIPPED`（接口返回 409）。

### 2.7 取消订单并回补库存

操作：

1. 找到 `PAID` 或 `PENDING` 订单；
2. 状态选择 `CANCELLED`；
3. 点击“更新”；
4. 查看订单详情中的商品；
5. 查询对应商品库存。

预期：

- 订单状态 `CANCELLED`；
- `cancelled_at` 有值；
- 每条明细的商品库存回补对应数量；
- 再次取消同一订单不会重复回补（状态已是终态，接口幂等）。

### 2.8 删除订单明细

操作：

1. 打开一个 `PENDING` 或 `PAID` 订单详情；
2. 订单至少有 2 条明细；
3. 点击某条明细的“删除”；
4. 确认。

预期：

- 明细删除；
- 该商品库存回补；
- 订单至少保留一条明细；只剩一条时删除按钮不可用/接口拒绝。

### 2.9 商品删除被引用拒绝

操作：

1. 用 API 或管理脚本尝试删除一个已被订单引用的商品；
2. 例如 `DELETE /api/products/<product_id>`。

预期：

- 返回 409；
- 商品仍在；
- 订单明细仍可查询。

### 2.10 删表演示

操作：

```bash
psql -h 127.0.0.1 -U db_owner -d course_db -f sql/06_drop_table_demo.sql
```

预期：

- `demo_drop_me` 创建、插入、查询、删除；
- 7 张核心业务表仍在；
- 不删除 `customer/orders/order_item/...`。

### 2.11 EXPLAIN 对比

操作：

```bash
psql -h 127.0.0.1 -U db_owner -d course_db -f sql/07_explain.sql
```

预期：

- 无索引状态 3 次计划；
- 建索引后 3 次计划；
- 保存完整输出到 `docs/evidence/IDX-01/`、`IDX-02/`；
- 报告中填 `{{EXPLAIN_BEFORE_MS}}`、`{{EXPLAIN_AFTER_MS}}`，不得编造。

### 2.12 并发测试

操作：

```bash
python3 scripts/benchmark_concurrency.py --clients 1,10,25,50 --duration 30
```

预期：

- 每级生成 CSV 与 summary JSON；
- 输出 TPS、p50/p95/p99、错误率；
- 测试后 `pg_stat_activity` 无残留业务连接；
- 报告填 `{{TPS_10}}`、`{{P95_50}}` 等占位符。

## 3. 演示失败预案

| 问题 | 处理 |
|---|---|
| 页面 503 | 查 `/health`、PostgreSQL 服务、`.env` 中 DB 配置 |
| 创建订单 409 库存不足 | 换库存充足商品；这是预期演示 |
| 状态更新 409 | 检查状态机，选择允许的目标状态 |
| 删除明细 409 | 订单只剩一条明细或状态不是 PENDING/PAID |
| 页面无数据 | 检查种子数据、筛选条件、分页 |
| CSRF 403 | 刷新页面获取新 token；确认页面 meta 与请求头 |
