> 项目：中小电商订单与仓储管理  
> 技术栈：PostgreSQL + Python Flask + psycopg2 原生 SQL + HTML/JS

## 1. 业务背景（约 300 字）

本项目面向一家经营日用消费品的中小电商企业。企业通过网页接收客户订单，订单中包含多种商品，商品归属于一个或多个分类；订单确认后需要扣减库存并生成物流单，供仓储和配送人员追踪。随着客户和订单数量增长，原先用表格人工登记的方式出现数据重复、库存账实不符、订单与物流信息脱节等问题。企业希望建立一个关系型数据库应用，把客户、商品、分类、订单、订单明细和物流单统一管理起来，支持按客户、状态和时间筛选订单，查看订单的多表关联详情，并在下单和取消时保证库存与订单状态一致。系统采用浏览器/服务器模式，数据库和 Flask 服务部署在 Linux 虚拟机上，Windows 主机只通过浏览器访问，适合课程环境下个人独立完成和演示。

## 2. 业务目标与范围

### 2.1 目标

1. 用关系模型表达客户、商品、分类、订单、明细、物流之间的业务联系；
2. 支持订单创建、查询、状态修改、明细删除和库存扣减/回补；
3. 覆盖 1-1、1-N、N-M 三种联系；
4. 通过事务保证“订单—明细—库存—物流”的一致性；
5. 通过索引与 EXPLAIN 展示查询优化；
6. 通过多客户端并发脚本记录访问性能；
7. 只做订单列表页和订单详情页两个业务页面。

### 2.2 范围内

- 客户、商品、分类、订单、订单明细、物流单的查询与维护；
- 订单创建时扣库存、生成物流单；
- 订单取消时回补库存；
- 订单明细删除时回补库存；
- 订单列表筛选、分页；
- 订单详情多表 join；
- 管理脚本建表、删表、种子数据、计数；
- EXPLAIN 与并发测试脚本。

### 2.3 范围外

- 购物车、支付网关、优惠券、推荐、搜索中台；
- 商家后台、复杂用户权限、会员体系；
- 商品图片、对象存储、消息队列、缓存、微服务；
- 完整 NoSQL 作业；
- 前端框架与 CDN。

## 5. 订单状态机

```text
PENDING --支付--> PAID --发货--> SHIPPED --完成--> COMPLETED
   |                |
   |                +--取消--> CANCELLED
   +--取消--> CANCELLED
```

| 当前状态 | 允许目标 | 说明 |
|---|---|---|
| `PENDING` | `PAID`、`CANCELLED` | 未支付可取消，取消回补库存 |
| `PAID` | `SHIPPED`、`CANCELLED` | 已支付未发货可取消，取消回补库存 |
| `SHIPPED` | `COMPLETED` | 已发货不能直接取消；如需退货走人工流程 |
| `COMPLETED` | 无 | 终态 |
| `CANCELLED` | 无 | 终态；重复取消不重复回补 |

**取消订单是否回补库存：是。** 规则如下：

1. 仅 `PENDING` 和 `PAID` 可取消；
2. 取消事务先锁定订单，再按订单明细逐商品 `stock = stock + quantity`；
3. 同一订单从非取消状态改为 `CANCELLED` 时只回补一次；
4. 已经是 `CANCELLED` 的订单再次请求取消，视为幂等，不再次回补；
5. 取消失败（例如订单不存在、状态非法）整体回滚，库存不变。

## 6. 订单明细合并规则

- `order_item` 的主键是 `(order_id, product_id)`；
- 同一订单中同一商品只能有一条明细；
- `POST /api/orders` 收到重复 `product_id` 时，先按商品合并，数量累加；
- 合并后再扣库存、插入明细；
- 数据库主键 `(order_id, product_id)` 作为最后一道防线，防止重复明细；
- 为了支持 `DELETE /api/order-items/<id>`，在 `order_item` 上增加一个 `order_item_id` 唯一代理列，但**不改变** `(order_id, product_id)` 主键。

## 8. 查询与候选索引映射

| 查询场景 | 主要 SQL 形态 | 候选索引 | 说明 |
|---|---|---|---|
| 客户订单历史 | `orders WHERE customer_id = ? ORDER BY created_at DESC` | `idx_orders_customer_created (customer_id, created_at DESC)` | 联合索引，避免排序 |
| 按状态筛选 | `orders WHERE status = ? ORDER BY created_at DESC` | `idx_orders_status_created (status, created_at DESC)` | 状态选择度视数据而定 |
| 订单详情明细 | `order_item WHERE order_id = ?` | 主键 `(order_id, product_id)` 前导列 | 主键即可 |
| 商品销售/明细反查 | `order_item WHERE product_id = ?` | `idx_order_item_product (product_id)` | 商品维度 |
| 分类商品列表 | `product_category WHERE category_id = ?` | `idx_product_category_category (category_id)` | N-M 反查 |
| 商品名称搜索 | `lower(product_name) LIKE ?` | `idx_product_name_lower (lower(product_name))` | 前缀搜索更有效 |
| 物流状态 | `shipment WHERE status = ?` | `idx_shipment_status_created (status, created_at DESC)` | 物流跟踪 |
| 访问日志 | `access_log ORDER BY created_at DESC` | `idx_access_log_created (created_at DESC)` | 运维查询 |

索引原则：

- 联合索引列顺序按“等值条件在前、范围/排序在后”；
- 不为低选择度布尔列单独建索引；
- 索引数量控制在 5~8 个，避免写放大；
- 最终是否被使用以 `EXPLAIN` 和 `pg_stat_user_indexes` 实测为准。
